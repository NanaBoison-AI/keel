# Decisions

Short log of non-obvious decisions.

- **Tailwind v3** chosen over v4 for stable PostCSS/config-based setup.
- **Routing:** hash routing (`createHashRouter`) so offline/PWA works without server config; `_redirects` still added for Cloudflare.
- **`tsx` as dev dependency** to run validator/index scripts.
- **Meditations quotes** were checked verbatim against the Project Gutenberg text of George Long's 1862 translation (ebook #15877). Gutenberg #2680 is the 1634 Casaubon translation and must not be used.
- **Meditations `year`** is set to 180 (year of Marcus's death); the work has no publication date.
- **Standalone seed cards** contain no direct quotes; refs cite book/chapter only where confident, otherwise the Part or principle name.
- **Swipe vs. scrolling:** when a card's text overflows, vertical swipes scroll it natively (a fade hints at more text). A swipe that _starts_ with the text already at its top/bottom edge chains to previous/next card; otherwise the ↑/↓ buttons do it. When the card fits, `@use-gesture` handles all directions. Left swipe works in both cases.
- **Tap handling:** single tap expands (`deeper`), double tap saves. The single tap waits 260 ms to rule out a double tap. Controls marked `data-nogesture` bypass use-gesture's click suppression.
- **Pillar weights** are stored as independent values (0–100, step 5) set with − / + steppers; changing one never touches the others. Sliders were dropped because they changed by accident while scrolling. The mix algorithm only uses relative weights, and Settings shows each pillar's derived share of the stack (`normalizeWeights`, so the shown shares always sum to 100). "Cards per day" uses a stepper for the same reason.
- **Daily stack** is persisted in the `daily` table on first open of the day, so later syncs or setting changes never reshuffle it. Cards are marked `seen` when displayed; the 90-day window is applied when the next day's stack is built.
- **Progress** has an optional `updatedAt` (not in the original spec) so "Continue" can pick the most recently read deck.
- **Removed packs:** a successful sync deletes cached packs no longer in `index.json`; progress and Notebook snapshots remain.
- **Dev server** serves `/content/*` from `./content` through a small Vite middleware (the production build does this in `build:index`).
- **Icons** are drawn as SVG (`public/icon.svg`) and rasterised to PNG with Chromium (192, 512, maskable 512, apple-touch 180).
- **Standalone pack titles** read "<Pillar>: Quick Reads" so the Library and card footers are unambiguous.
- **Audit (local, mobile):** Lighthouse accessibility 100 / best-practices 100; axe (WCAG A/AA) clean on all screens in light and dark. Offline verified with Chromium: after the first online load, Today, Library and decks render with the network disabled. Still to do: real-device check on iOS Safari and Android Chrome.
- **Mentor pillar (10th):** the only AI-written pillar, enforced by the validator (`pillar: "mentor"` ⇔ `origin: "ai"`, series only, no quotes/sources/author/year). Every Mentor card and Library entry says "Written by Claude"; About explains the boundary. Default weights are now family 15 / mentor 10 (others unchanged, still sum to 100).
- **Weights migration:** `completeWeights` fills any pillar missing from saved weights from the defaults and rescales to 100, preserving the user's relative choices. Complete weights are never touched, so the independent stepper values stay as set.
- **`mentor-curriculum.json`** is validated but never shipped: `build-index.ts` only copies the four pack folders.
- Library type label for `origin: "ai"` packs is "Lesson"; the Series type filter still includes them.
- **Lighter look (user feedback: "too serious"):** fonts are now Fraunces (headings) + Nunito (body/UI) instead of Literata + Inter; palette is "sunlit harbour" (navy #18304a, cream #fff8ec, sea #167b96, amber #f2a03d) with pastel pillar chips; reading base size 16/18/20/22px. All chip and accent pairs checked at ≥4.5:1 (axe clean in light and dark). Icon and manifest colours updated to match. CLAUDE.md §3 and §6 updated.
- **Today navigation:** because the top dots show position, Today swipes left/right to move, swipe up opens the book (`/deck/<pack>`, resuming), double-tap bookmarks, and a thumbs-down button beside the bookmark replaces the ⋯ menu (swipe-left "less like this" is gone there). The ↑/↓ buttons are removed on Today; keyboard arrows and screen-reader-only buttons remain. Deck view is unchanged (vertical swipes, ⋯ menu).
- **Swipe-up hint:** Today shows "Swipe up to read the book" (bobbing arrow, static under reduced motion) under card 1 only, until the reader has opened a book with a swipe up once (`hintOpenBook` setting). It never appears in deck view and never nags on later cards.
- **Deck view controls:** same toolbar as Today (thumbs-down + bookmark); the ↑/↓ buttons and ⋯ menu are removed there too. Vertical swipes still navigate decks and swipe-left is still "less like this"; keyboard arrows and screen-reader-only buttons keep non-touch access.
- **Raised reading card:** the card is inset 12px from the screen edges, rounded (28px), white (lifted navy in dark mode) with a border and a soft two-layer shadow; the shadow is kept small so the stack surface (which clips slide animations) does not cut it into a hard band. Library/Journey cards got a slightly stronger shadow to match. On a long card, swipe up scrolls the text first and moves on once the text is at its end.
- **Keep screen on:** while a card is on screen (Today and decks) the app holds a Screen Wake Lock, released after 10 minutes without a touch and re-taken on the next touch or when the app returns to the foreground (browsers drop it when hidden). Setting "Keep screen on while reading", default on; disabled with a note where the API is unsupported. Settings must now finish loading before Today builds its stack, so saved pillar weights are never overridden by defaults on a cold start.
- **Vertical swipes on scrolling cards (fix):** the card container is always `touch-action: pan-y`; a touch handler watches each vertical swipe and reads the scroll position at that moment (`src/lib/swipe.ts`). If the swipe scrolled the text to its end and the finger kept going (60px, or 30px for a quick flick), it moves to the next card (Today: opens the book); the same at the top goes back. One swipe is enough on a card that barely overflows, and on a card that fits any swipe counts. This replaced a "does it scroll?" measurement that could go stale. Root cause of "swipe up doesn't work on a card with a scroll": the scroll element's ref was cleared when the outgoing card unmounted after its exit animation, so from the second card on the scroll-aware handling had nothing to read. The ref is now only ever set, never cleared by a leaving card (regression test in `tests/ui.test.tsx`).
- **Horizontal-only navigation (supersedes the vertical-swipe entries above):** Today and decks both move with swipe left (next) / swipe right (previous). Swipe up/down, the scroll-chaining touch handler (`src/lib/swipe.ts`) and the "Swipe up to read the book" hint were removed; vertical drags just scroll the card text (`touch-action: pan-y`). Swipe-left no longer means "less like this" in decks; thumbs-down is the only way. Today gets a visible open-book button (thumbs-down, open book, bookmark) in place of swipe-up. The scroll-ref fix from the earlier chaining work is gone with the code it protected.
- **Deck header:** the "Card N of M" count is replaced by the same progress stepper as Today, under a small "← deck title" link. Decks with more than 14 cards (books up to 20, briefings up to 25) use compact dots so the stepper fits a 320px phone. The stepper keeps its `progressbar` role and "Card N of M" accessible label for screen readers.
- **Swipe animation:** each card is a `motion` draggable (`drag="x"`, direction-locked) so it tracks the finger; on release `swipeDirection` (`src/lib/swipe.ts`: 80px, or 30px at 500px/s) decides next / previous / spring back. Entering and leaving cards translate fully across the screen with a spring and a slight scale, with no opacity change (the old cross-fade looked like a blink). `@use-gesture` now only handles taps (expand, double-tap save). The scrolling text box needs `touch-action: pan-y` of its own: touch-action does not pass through a scroll container, so without it the browser cancelled sideways swipes that began on the text (`pointercancel`) even though mouse drags worked. Reduced motion: crossfade, no slide.
